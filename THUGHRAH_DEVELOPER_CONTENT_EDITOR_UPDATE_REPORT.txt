تقرير تحديث لوحة المطور وإدارة محتوى ثغرة

ملخص التنفيذ:
- تم تطوير لوحة المطور دون حذف الهوية أو تغيير النصوص الحالية للقضايا.
- تم إنشاء نموذج إضافة/تعديل قضية مرن لا يفرض خطًا زمنيًا أو مؤشرات أو مراجع أو أسئلة.
- تم تجهيز إدارة محتوى الموقع بمفاتيح منظمة مثل home.hero.title و social.telegram.
- تم تجهيز وضع تحرير مباشر للمعاينة داخل لوحة المطور، مع إبقاء الحفظ الحقيقي مشروطًا بربط API محمي.
- تم توسيع مخطط Cloudflare D1 المستقبلي ليشمل جداول القضايا، الأقسام، الخط الزمني، المؤشرات، المستندات، المراجع، الأسئلة، الملاحظات المهنية، محتوى الموقع، وسجل التعديلات.

الملفات المعدلة:
- src/DeveloperDashboard.tsx
- src/auth/types.ts
- functions/_utils/auth.js
- cloudflare/d1/schema.sql
- cloudflare/README_AUTH_AND_D1.md

الملفات المنشأة:
- functions/api/content/index.js
- functions/api/content/[key].js
- THUGHRAH_DEVELOPER_CONTENT_EDITOR_UPDATE_REPORT.txt

ما أصبح جاهزًا:
- نموذج مرن لإضافة وتعديل القضايا.
- اختيار التصنيف من تصنيفات الموقع الحالية المستخدمة في الواجهة.
- إضافة وحذف خط زمني، مؤشرات اشتباه، مستندات، مراجع، أسئلة تدريبية، وملاحظات مهنية.
- معاينة للقضية بنفس الهوية الداكنة والمنظمة دون إظهار الأقسام الفارغة.
- إدارة محتوى الموقع من لوحة المطور عبر مفاتيح ثابتة.
- معاينة وضع التحرير المباشر للنصوص القابلة للتعديل.
- مسارات API محمية مبدئيًا لإدارة محتوى الموقع.
- مخطط D1 تفصيلي للحفظ المستقبلي.

ما يحتاج إعدادًا لاحقًا:
- ربط Cloudflare D1 فعليًا وإضافة binding باسم DB.
- تحويل مسارات functions/api/cases و functions/api/content من رسائل 501 إلى عمليات قراءة/حفظ فعلية.
- إضافة سجل تعديلات فعلي عند كل حفظ أو حذف أو نشر.
- نقل القضايا تدريجيًا من الكود الثابت إلى قاعدة البيانات دون تغيير محتواها أو روابطها.
- ربط وضع التحرير المباشر بصفحات الموقع العامة بعد اعتماد مفاتيح المحتوى النهائية.

اختبار البناء:
- تم تشغيل npm run build بنجاح.
- ظهر تحذير حجم bundle فقط، وليس خطأ بناء.
